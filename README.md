# DeepSeek V4-Flash Vision RAG

> 让 AI **真正"看懂"** 一份 PDF，然后你对它提问：它告诉你答案、答案在第几页，
> 并把那一页的原图展示出来给你核对。

基于 DeepSeek 视觉大模型 `deepseek-v4-flash-vision-exp` 的 PDF 深度问答与检索
（vision RAG）agent skill。支持文字版 PDF，也支持**扫描版**；能看懂
**图表、表格、代码块、公式**，而不只是认字。

---

## 一、它能做什么

| 你说 | 它做 |
|---|---|
| "帮我读一下这份 120 页的手册" | 逐页视觉阅读，建立可检索的索引（约 2 分钟，只需一次） |
| "审批策略出厂默认是什么？" | 给出答案，标注 `[第6页]`，并把第 6 页原图给你看 |
| "§05 在第几页？讲了什么？" | 定位章节起止页码 + 内容总结 |
| "这个概念在哪几页被提到？" | 找齐全书所有相关页（跨页召回） |
| "给我看看第 72 页" | 高清渲染该页图片 |
| "对比一下 XX 和 YY" | 基于相关页内容做深度对比分析 |

每次回答都会生成一个**自包含 HTML 预览页**（答案 + 全部引用页原图内嵌其中），
双击浏览器打开即可查看，无需联网。

| 重复提问 | 索引缓存命中，零重建成本 |

## 三、工作原理（通俗版）

整个系统就做两件事，像人读一本书：

### 第一阶段：读一遍书，做笔记（ingest，一次性）

```
PDF ──渲染──> 每页一张图片 ──上传──> DeepSeek 文件服务器
                │                        │
                └──抽取文字层──┐         ↓
                               │   视觉模型逐页"阅读"
                               │   （25 页打包进 1 个请求，
                               │    吃满 100 万 token 上下文）
                               ↓         ↓
                          index.json（每页一张"读书卡片"）
```

模型每读一页，就写一张卡片——**这就是 `index.json`**。第 22 页的真实卡片长这样：

```json
{"page": 22,
 "type": "正文",
 "headings": [{"level": 1, "text": "§03 四种模式，人话版"}],
 "summary": "介绍四种模式：标准、PTC、极简、创造，并指出它们不在同一维度上，标准模式是默认。",
 "keywords": ["四种模式", "标准", "PTC", "极简", "创造"]}
```

120 张卡片 + 每页文字层 + 由标题派生的全书大纲，一起存进缓存。
**从此这本书就被"读过了"，这个步骤永远不用再做。**

### 第二阶段：按笔记翻书，回答问题（ask，每次提问）

```
你的问题
   ↓ ① 查卡片     本地在 index.json 里筛出最可能的 12 页（毫秒级，零费用）
   ↓ ② 看图确认   模型看这 12 页截图，挑出真正相关的 4 页（第 1 次 API 调用）
   ↓ ③ 深读作答   这 4 页 ± 前后邻页原图摊开，开推理模式仔细读（第 2 次 API 调用）
   ↓
答案（每个论点标 [第N页]）+ 引用页图片 + 自包含 HTML 预览
```

**为什么是三层漏斗？**——便宜的方法粗定位、贵的眼睛做确认、最贵的推理只用在
刀刃上。120 页 → 12 页（免费）→ 4 页（关推理，快）→ 深读（开推理，质量）。

### ① "查卡片"具体怎么查（本地检索，零 API 成本）

用经典的 TF-IDF 关键词打分，全程只是 Python 字符串运算：

1. **分词**：中文没有空格，就把每个连续中文段切成二字滑窗——
   "审批策略" → `审批 / 批策 / 策略`；英文按整词取；再去掉"什么""怎么"这类停用词
2. **造页面文档**：每页 = 标题、摘要、关键词各重复 3 遍 + 整页文字层 1 遍
   （重复 3 遍 = 权重×3：摘要里出现"审批"比正文顺嘴提一句重要 3 倍）
3. **打分**：`页面得分 = Σ 词的稀有度(idf) × min(出现次数, 8)`
   - idf 让稀有词值钱：只出现在 1 页的词值 4.80，全书 35 页都有的"默认"只值 1.49
     ——防止高频词让无关页霸榜
   - 次数封顶 8：防止某页重复写 20 次"默认"就压过真正讲审批的页
4. **排序取前 12 名**，交给第 ② 步

词面匹配有盲区（词对但主题不对的噪声页、主题对但用词不同的漏网页），所以
第 ② 步必须让模型**看图**凭内容确认——两道关卡各司其职。

## 四、为什么不用更简单的方案

| 方案 | 每次提问的成本 | 看得懂图表/扫描件吗 | 页码引用 |
|---|---|---|---|
| A. 每次把整本 PDF 塞给模型 | 约 4.6 万图片 token，几十秒 | 能 | 能 |
| B. 传统文本 RAG（只搜文字） | 便宜快 | **不能** | 常错 |
| C. PageIndex（本项目的参考原型） | 只生成目录树，**没有问答** | 不能 | 靠模型猜+修复循环 |
| **本 skill** | **2 次调用、几千 token、秒级** | **能**（看的是页面图） | **天然精确** |

页码为什么天然精确：每张图片就是"第 N 页"渲染出来的，卡片上标注 `[第N页]`
标签后交给模型——页码来自物理事实，不需要模型猜。PageIndex 项目 80% 的代码
花在"让文字模型猜章节页码 → 验证 → 修复"上，本方案让这个环节整体不存在。

## 五、快速上手

### 环境要求

```bash
pip install openai pymupdf   # 本机一般已装好
```

API key 默认内置；可用环境变量 `DEEPSEEK_API_KEY` 覆盖。

### 1. 建索引（每份 PDF 一次）

```bash
python scripts/ingest.py "你的文件.pdf"
```

- 120 页约 2~3 分钟；重复运行直接命中缓存，瞬间返回
- 常用参数：`--force` 重建索引｜`--limit 50` 先索引前 50 页试水｜`--clean` 清缓存
- 大文档建议先 `--limit 30` 看看页型分布对不对，再跑全量

### 2. 提问

```bash
python scripts/ask.py "你的文件.pdf" "审批策略出厂默认是什么？"
```

输出四段：`=== 答案 ===`（带 [第N页] 引用）、`=== 引用页 ===`、
`=== 页面图片 ===`（PNG 已复制到 `./pdf-vision-out/`）、`=== 预览 ===`
（HTML 文件路径，双击浏览器打开）。

可调参数：`--top 4` 深读页数｜`--cands 12` 粗筛候选数｜`--no-images` 不出图片。

### 3. 看指定页

```bash
python scripts/show.py "你的文件.pdf" --pages 6,33 [--dpi 220]
```

高清渲染指定页，无需先建索引。

## 七、成本账

| 操作 | API 调用 | 图片 token | 说明 |
|---|---|---|---|
| 建索引（120 页） | 5 次批量 + 120 次上传 | 约 4.6 万 | 一次付费，永久复用 |
| 提问 | 2 次 | 约 0.6~1.5 万 | 精排 12 图 + 深读约 10 图 |
| 看指定页 | 0 次 | 0 | 纯本地渲染 |

单图 token 封顶 384（API 自动缩放到约 800×800），所以页数翻倍成本才翻倍，
图片分辨率不影响费用。

## 八、DeepSeek API 要点（实测踩坑记录，详版见 references/api-notes.md）

1. **默认是推理模型**：reasoning 计入 `max_tokens`，预算小了会得到**空 content**
   且不报错。本 skill 对批量任务用 `extra_body={"thinking":{"type":"disabled"}}`
   关推理（快/省/稳），深读回答时再打开（质量）。
2. **JSON Output 偶发空回复**：所有调用都带重试 + 指数退避，不要绕过
   `ds_client.py` 直接调 SDK。
3. **Files API**：页图上传一次永久复用（file_id），绕开 48MiB 请求体限制；
   失效自动检测重传。
4. **批量打包**：25 页/请求，`[第N页]` 文本标签与图片交错排列，页码不会乱；
   截断自动对半拆批。

## 九、常见问题

**Q：索引建到一半断了/换电脑了，要重来吗？**
页图上传支持断点续传（files.json 记录进度）；模型分析按批推进。重跑同一条
命令会从断点继续。换电脑则服务端 file_id 仍在，只需拷走 `.cache/` 目录。

**Q：PDF 改了一个字，索引会更新吗？**
缓存键是 PDF 内容哈希，内容变了会自动另建新缓存，不会读旧索引。旧缓存可用
`--clean` 删（服务端文件配额 25GiB/1 万个，一般不用管）。

**Q：扫描版（纯图片、无文字层）能用吗？**
能。索引靠的是视觉阅读；只是本地粗筛少了文字层加持，会更依赖摘要/关键词，
通常多一两秒精排兜底，准确性不受影响。

**Q：一本 500 页的书要建多久？**
大致线性外推：500 页约 10 分钟索引（21 次批量调用），之后每次提问仍是
2 次调用秒级响应。

**Q：为什么答案里的页码和 PDF 阅读器显示的页码有时差 1~2 页？**
本 skill 用的是**物理页码**（第 1 张图 = 第 1 页）。书有自己的印刷页码
（正文从"第 1 页"起算），两者天然差一个前言偏移。答案统一按物理页码引用，
展示的原图就是证据，不会有歧义。

**Q：能同时索引多份 PDF 吗？**
可以，各自独立缓存。跨文档对比目前需手动分别提问。

## 十、已知局限

- 超长跨页内容（如一张表横跨 3 页）深读时只带 ±1 邻页，极端情况需手动
  `show.py` 看全
- 纯语音/视频型 PDF 不支持；加密 PDF 需先解密
- 深读单次上限约 10 页上下文，问题涉及全书统计（"全书一共提到几次X"）时
  精度会下降——这是 RAG 的固有权衡，换取的是秒级响应
